# Revise Story

1. Run `story-review` at the highest useful edit level unless the user already supplied accepted revision notes.
2. Rank accepted findings by causal impact.
3. Use `revise-story` to patch architecture before sentences when the problem is structural.
4. Re-run `scene-outline` only if scene order or function changes.
5. Run `story-state` after accepted changes to chronology, knowledge, props, questions, promises, relationships, or life state.
6. Run the `revise-story` prose pass only after higher-level changes settle.
7. Run `continuity-check` and the style checker.

Done when every accepted finding is fixed or explicitly declined, narrative state matches the revision, and lower-level polish does not hide an unresolved structural problem.
